How to submit a GeoTIFF to DrivenData

The public site offers one historical reference file for download. This walkthrough explains how an authorized competitor uploads a file and what must be checked first. It does not imply that the reference copy is a new or holdout-qualified prediction.

Important before clicking submit. The available H19-5 file is a copy from the linked 19GEMSDOE site. This checkout has not compared it byte-for-byte or pixel-for-pixel with the official sample submission, and the public leaderboard does not expose the evaluated file hash. Do not use a weekly feedback slot to re-submit it unless you have checked that it is needed and verified the official template.

Upload steps

One file, one note, one final check

  1. Download the `.tif` above. Keep the original filename and verify its SHA-256 if you move or rename it. Do not unzip or edit the raster.
  2. Validate it against the official template. If you have authorized access to `sample_submission.tif`, install the project requirements and run: 
    python scripts/validate_submission.py \
  --template data/sample_submission.tif \
  --prediction /path/to/gems19-h19-5-powerlaw-budget-multiline-corroborated-20260930-e27054cf-nan.tif
    The local reference audit has checked TIFF structure, one float32 band, EPSG:32611 metadata, 100 m pixel scale, and that every finite value is exactly 0 or 1. It has **not** checked exact bounds/transform equality to DrivenData's template in this checkout.
  3. Open the official submission form. Sign in to the account or team that is registered for the competition, then open GEMS Submissions.
  4. Choose the file. On “New submission,” select the GeoTIFF in “File to submit.” The competition page accepts a single-band GeoTIFF or a ZIP containing one GeoTIFF. Use the `.tif` directly here.
  5. Add the note. Paste the unique identifying note shown above, or use a more specific strategy and artifact ID. The note is for your team's record; it does not change the score.
  6. Submit and record the response. Save the submission name, public score, UTC time, and file SHA-256 in the project registry. Public leaderboard results are not private Phase 1 scores or final Phase 2 scores.

The competition rules permit up to three weekly feedback submissions subject to the website limit, but require choosing only one final submission across both prize rounds. Respect the account's current allowance shown by DrivenData.

Prevent the range error

Check the scored footprint, not just the whole-file min/max

Every in-footprint value must be finite and within `[0,1]`. NaN is only acceptable outside the official bounds. A nodata value, NaN, infinity, or sentinel inside the valid footprint can trigger “Predicted values must be in range [0, 1]”.

Protect the experiment

Don't turn the leaderboard into your holdout

A new method must first beat the frozen incumbent on the spatially blocked known-fault proxy. If no true local holdout gain is recorded, do not use a scarce weekly submission slot to explore an unvalidated idea.

Official contract

Before a model-generated file is recommended

The competition describes one 32-bit-float band in EPSG:32611 at 100 m, identical bounds to the training grid, values `[0,1]`, and null/NaN outside the bounds. The sample submission is the authoritative way to check the exact grid. See the official format and official prize rules.

AI disclosure: the official rules allow generative AI but require applicable use to be stated in the narrative. Ensure any final competition narrative accurately describes which parts were AI-assisted.
