How we prevent the [0, 1] range error

Exact footprint masking & IEEE-754 NaN outside

DrivenData rejects any upload with "Predicted values must be in range [0, 1]" if even one pixel inside the 5,167,373-pixel valid footprint is NaN, Inf, < 0, or > 1, or if outside-footprint pixels use numeric sentinels like -9999 instead of NaN. Our pipeline enforces np.clip(inside, 0.0, 1.0) on the 5,167,373 valid pixels and np.nan on all 7,111,787 outside-footprint pixels, verified after disk write.
