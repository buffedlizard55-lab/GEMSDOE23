Step by step

Upload procedure

  1. Download gemsdoe23-h30-arrangement-matched-habitat-20261002-0d4e02e8-nan.tif with the button above. It is the official variant: NaN outside the footprint, exactly as the format rules require.
  2. Sign in at drivendata.org/competitions/306 and open the Submissions tab. The account must be the entity registered for this competition.
  3. Upload the .tif unchanged. Do not open and re-save it in GIS software: that rewrites the nodata tag and can turn NaN into a large negative sentinel.
  4. Paste the note from the copy box above into the submission description field. It records the method, the emitted pixel count, η and the file hash, so the upload is traceable back to this repository.
  5. Record the score the moment it appears: python scripts/record_score.py --score <X> --id 38539dc6. The script finds the uploaded file by that hash, logs the score, adds the file as a 25th anchor (in the same cross-validation family as the other emissions built from the H24 ranking) and refits into docs/data/habitat-model-refit.json; the committed model is left untouched so the shipped files stay reproducible. Every live score tightens the |G| and skill estimates on the evidence page.
If the uploader rejects the file with “Predicted values must be in range [0, 1]”, upload the all-finite variant instead (gemsdoe23-h30-arrangement-matched-habitat-20261002-0d4e02e8-allfinite.tif). It is byte-identical inside the footprint and writes 0.0 rather than NaN outside it; some server-side checkers read the whole array before applying the footprint mask. Both variants are produced and validated by scripts/build_audited_emission.py (H24: scripts/build_submission_live.py).

Rules that constrain the decision

Before you spend the slot

Three uploads per rolling seven days

Official rules §3.2/§3.4 (re-read 2026-10-02); the competition closes 3 December 2026, 23:59 UTC, about nine weeks, so at most about 26 uploads remain. Slots are the only ground-truth channel, so the standing rule in this repository is: never upload something that has not beaten the current best on a validated holdout. That rule cannot be satisfied honestly: no offline proxy correlates with the live board (best ρ = 0.326) and no blocked holdout can test hidden-fault placement. This session adds an arrangement audit that orders the live scores, but it is correlational and post-hoc, so it does not replace the rule.

Which file, and what to expect

H30 (the download above) has the same ranking as H24 with the audit defects removed and an arrangement in the bin that holds the best live scores. H29 is the same ranking as a de-aliased lattice; H24 is superseded. Central expectation if TP per emitted pixel matches h19-5 (live 0.1922): DTI 0.17–0.18; scenario range 0.08–0.40 depends on whether placement skill survives the arrangement. An upload would therefore most likely equal the group's best, not beat it; the leader is at 0.3195. If a slot is spent, record the score immediately (scripts/record_score.py) and refit: one live observation is worth more than more offline work.

If you want slots to buy information, not score

Hypothesis H-32 on the hypotheses page sketches two controlled pairs (arrangement: H29 vs H30; near-field band vs a score-matched control) with pre-registered readouts. Spending slots that way overrides the standing rule, so it is the owner's decision, not an automatic one.

One submission for both prize rounds

The same file is scored on the private test set at the close (Initial Round, 5 × $10,000) and re-scored against the expanded expert labels in the Final Round ($250,000 pool). Known USGS/INGENIOUS fault pixels are masked out in both rounds (staff ruling, forum 11516), so nothing is gained by painting the catalogue.
